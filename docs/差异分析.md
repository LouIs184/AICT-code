# AICTVer2 vs TMCode — 训练差异分析文档

> 背景：AICTVer2（本项目）与 TMCode（同学项目，位于 `./TMCode`）都是做 CT 投影域去 PBI 伪影（PBI 条纹校正）的。用 AICTVer2 训练出来的效果比同学差很多。
> 本文基于**两边代码**逐项对比，找出其中的致命差异与次要差异。
> 结论：任务、数据域、归一化基本一致，但**训练方法上有 4 处致命区别**，其中「损失函数」这一条就足以解释效果差距。

---

## 1. 一句话结论

| 排名 | 差异 | 严重度 |
|------|------|--------|
| 1 | 损失函数：纯 MSE vs 六项复合损失（L1+伪影L1+SSIM+FFT+角度梯度+Sobel） | 🔴 致命 |
| 2 | 模型输出：恒等起点的伪影残差 vs 随机初始化的直接回归 | 🔴 致命 |
| 3 | 归一化：InstanceNorm vs BatchNorm | 🔴 致命 |
| 4 | 训练稳定性：梯度裁剪 clip_grad_value_(0.01) vs 无裁剪 | 🟠 重要 |
| 5 | 优化器/调度器/batch/归一化范围 | 🟡 次要 |

## 3. 致命差异详解

### 3.1 🔴 损失函数：纯 MSE vs 六项复合损失

**这是最致命的一条。**

AICTVer2 实际跑的 ProjCT 配置（`experiments/denseunet_projct.yaml`）只有 MSE 生效：

```yaml
loss:
  mse_weight: 1.0
  charbonnier_weight: 0.0
  ssim_weight: 0.0
  vgg_weight: 0.0
  adv_weight: 0.0
  tv_weight: 0.0
  # ffl_weight / hard_weight 等全部被注释
```

`runs/2026-0807-1230-DenseUNet-ProjCT/checkpoints/config.yaml` 也确认 `ffl_weight: 0.0`、`ssim_weight: 0.0`。代码库里已实现的 `FocalFrequencyLoss`（`src/losses/focal_frequency.py`）没有启用。

TMCode 的损失组合（`train_fbpconvnet_sino.py:106-113`）：

```python
loss = 0.3 * loss_l1
     + 0.1 * loss_res          # 伪影残差 L1：L1(pred_artifact, gt_artifact)
     + 0.8 * loss_ssim         # 1 - SSIM
     + 0.8 * loss_fft          # FFT 幅值域 L1（log1p|FFT|）
     + 0.8 * loss_angular      # 沿投影轴向一维梯度 L1
     + 0.3 * loss_sobel        # 0°/90°/45°/135° 多向梯度 L1
```

**为什么致命：** PBI 条纹是**周期性、能量远小于主体图像**的。纯 MSE 被主体图像主导，网络只要"复制输入（≈恒等映射）"就能把 MSE 压得很低，永远学不会去除条纹。而同学的：

- `log_fft_loss`（train:44-50）在频域幅值上算 L1，**直接惩罚条纹所在频率**；
- `angular_grad_loss`（train:52-56）约束条纹方向的梯度；
- `loss_res`（train:83,96）**显式监督伪影本身** `gt_artifact = lq_sino - gt_sino`，逼网络把"伪影"学出来而不是糊过去；
- SSIM + 多向 Sobel 补充结构约束。

### 3.2 🔴 模型输出形态：恒等起点的伪影残差 vs 直接回归

TMCode 的 `ResidualFBPConvNet`（`models.py:574-577, 597`）：

```python
# 输出层近零初始化 → 训练一开始 predicted_artifact ≈ 0
nn.init.normal_(self.outc.weight, mean=0.0, std=0.001)
nn.init.constant_(self.outc.bias, 0.0)
...
clean_img = input_img - predicted_artifact   # 模型输出"伪影"，相减得到干净图
```

→ 训练开始时模型**≈ 恒等映射**（输出≈输入）。对"输入已经接近干净、只需去掉伪影"的任务，这是极强的先验：优化路径短、起点稳定、不会在开头就把整幅图像搞坏。

AICTVer2 的 DenseUNet（`src/models/unet.py:166`）是 `F.relu(x + conv6)`：

- 也是残差形式，但 `conv6` 是随机初始化，没有恒等起点；
- 没有显式的"伪影"监督目标，网络学的是整幅图的回归；
- `F.relu` 还会把输出钳制到非负。

### 3.3 🔴 InstanceNorm vs BatchNorm

- TMCode：`InstanceNorm2d`（`models.py:495-506, 547`），注释明确写"instance 推荐用于医学图像生成/去噪"。
- AICTVer2：`BatchNorm2d`（`src/models/blocks.py:20`），全网络各处使用。

**为什么重要：** 医学数据病人之间域差异大，逐样本归一化的 InstanceNorm 明显优于按 batch 统计的 BatchNorm。而且同学 `batch_size=1` 本来就不能用 BN，两者是配套的。你 batch=36 时 BN 会把不同病人的统计量混在一起，削弱去伪影能力。

### 3.4 🟠 梯度裁剪

TMCode `train_fbpconvnet_sino.py:116`：

```python
torch.nn.utils.clip_grad_value_(model.parameters(), clip_value=grad_max)  # grad_max=0.01
```

FFT、梯度类损失梯度很大，不裁剪容易震荡/发散。AICTVer2 的 `src/trainer.py:393-395` 没有任何梯度裁剪。

## 4. 次要差异

| 维度 | AICTVer2 | TMCode | 说明 |
|------|----------|--------|------|
| 优化器 | Adam, wd=0 | AdamW, wd=1e-4 | 影响较小 |
| 调度器 | StepLR(step=2, γ=0.95)，每2轮衰减 | CosineAnnealing(T_max=150, eta_min=1e-6) | StepLR 前期衰减偏快，影响较小 |
| batch size | 36 | 1 | 与 BN/IN 选择相关（见 3.3） |
| 归一化范围 | clip[0,0.28] | (x)/0.3，负数置0 | 接近 |
| 是否裁剪视角边缘 | crop_rows=16 | 不裁剪 | 接近 |

## 5. 需要注意的坑

### 5.1 TMCode 数据形状自相矛盾（需向同学确认）

- 训练脚本注释写 `[B,1,512,720]`（整幅正弦图，`train_fbpconvnet_sino.py:79-80`）；
- 但 `datasets.py:48` 实际 reshape 是 `(128,512)`（单视角大小）。

两者不一致。若同学实际用的是 `(128,512)` 单视角，则两边数据粒度一致；若是 `(512,720)` 整幅正弦图，则同学的模型能"看见"视角方向的结构，而你这边 `proj_reader.py` 每次只读**一个视角**，看不到视角方向——这是结构性的差异，指标无法直接对比。**务必先确认。**

### 5.2 AICTVer2 的 SSIM 实现有隐患

`src/losses/ssim.py:32-36` 在 SSIM 计算内部对输入做了 per-image min-max 归一化，会**抹掉绝对强度信息**。以后如果要开 SSIM 损失，需要先修正这个实现，否则损失失真。

### 5.3 对比口径

AICTVer2 验证指标是 MSE / PSNR / SSIM（图像域），TMCode 是 L1 / SSIM（投影域）。两边指标和评价域不同，数字没有直接可比性。

---

## 6. 建议的修改顺序（按投入产出）

1. **损失改成同学的组合**（性价比最高）：
   - 打开 `experiments/denseunet_projct.yaml` 里的 `ffl_weight`；
   - 或直接抄同学的 `log_fft_loss` + `angular_grad_loss` + SSIM；
   - 加一项显式伪影残差 L1：`gt_artifact = lq - gt`。
2. **模型改成伪影残差 + 输出层近零初始化**（恒等起点），顺手把 BN 换成 InstanceNorm。
3. **加梯度裁剪**：`torch.nn.utils.clip_grad_value_(model.parameters(), 0.01)`。
4. 与同学确认数据粒度、归一化、评价口径是否一致，再对比数字。
